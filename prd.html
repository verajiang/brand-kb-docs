MVP Product Requirement Document

品牌服务知识库 MVP 第一版 PRD

把散落在会议、聊天、复盘和 Brief 中的品牌服务信息，转化为可信、可追溯、可持续更新的品牌知识库，让新人和协作方快速理解一个品牌项目。

完整 Web App Postgres 主存储 Markdown 双写导出 AI 自动入库 + 人工抽审

1. 产品定义

一句话定义

品牌服务知识库是一个面向品牌服务团队的项目上下文中枢，帮助每个经手品牌的人快速知道项目背景、当前状态、关键风险、长期原则和下一步行动。

核心闭环

Web 端上传/粘贴沟通记录 → 保存原始材料 → AI 解析结构化品牌知识 → 自动入库，人可抽审 → 生成新人速览看板与 Markdown 归档。

2. MVP 范围

第一版必须包含

  • 品牌项目档案：基础信息、业务阶段、核心目标、主要问题、合作机会。
  • 上游资料输入：粘贴文本、上传文本类文件、选择来源类型、保存完整原始材料。
  • AI 结构化解析：识别品牌、材料类型、长期原则、阶段关注、商机风险、PM Top 5、待确认问题。
  • 自动入库 + 人工抽审：唯一识别品牌时自动入库，无法识别时进入人工确认。
  • 新人速览看板：展示品牌总览、当前重点、原则、风险、行动、问题与更新记录。
  • Markdown 双写导出：数据库为主，同时导出主文档和 source 原文归档。

第一版暂不包含

  • 后台监听微信、飞书、钉钉。
  • 自动读取企业 IM。
  • 完整 OCR 和图片/视频/直播间画面视觉理解。
  • 完整 RBAC 权限体系。
  • 多品牌经营管理驾驶舱。
  • 自动向客户发送消息或替 PM 做业务决策。

3. 用户与场景

PM / 品牌服务负责人

上传沟通记录、更新知识、查看 Top 5 行动、判断风险和商机。

新接手同学

快速了解品牌背景、长期禁忌、当前重点、关键联系人和历史决策。

执行协同方

查看与内容、媒介、投放、直播、数据相关的偏好、禁忌和行动。

管理者

查看品牌服务是否有沉淀，判断当前风险是否被识别和跟进。

4. 信息架构

一级页面目标关键内容
登录页轻量身份识别登录、上传人/抽审人记录、品牌访问基础控制
品牌列表页快速找到品牌搜索、品牌卡片、高风险数、待确认数、行动数
品牌详情页10 分钟理解品牌新人速览、联系人、长期原则、阶段关注、商机风险、行动、问题、更新记录
上传资料页上游数据输入目标品牌、来源类型、材料时间、文本/文件、自动入库开关
待确认 / 抽审页控制 AI 风险品牌确认、多品牌材料、低置信度结论、撤回更新
Markdown 导出页保留知识库归档品牌主文档、source 原文归档、导出记录

5. 核心流程

1
Web 端上传 / 粘贴会议、聊天、复盘或 Brief。
2
系统保存完整 source 原始材料，记录来源类型、材料时间、上传人。
3
AI 判断材料类型并提取结构化品牌服务内容。
4
输出长期原则、阶段关注、商机风险、PM Top 5 行动和待确认问题。
5
若能唯一识别品牌则自动入库；否则进入人工确认。
6
品牌看板读取最新数据，并同步生成 Markdown 主文档与 source 归档。

6. 页面原型说明

品牌列表页

包含搜索、新建品牌、上传资料和品牌卡片。品牌卡片展示行业、业务阶段、更新时间、高风险、待确认、行动数和状态。

上传资料页

包含目标品牌、来源类型、材料时间、原始文本、文件上传、自动入库开关和解析结果。

品牌详情页

包含 8 个 Tab，首屏优先展示新人速览：核心目标、主要问题、关键数字、重要行动和高风险。

待确认 / 抽审页

处理品牌缺失、多品牌、低置信度、AI 自动入库抽审，支持确认、修改、撤回。

7. 数据规则

类型规则
证据等级品牌明示、品牌行为、项目结果、服务方观察、待确认。
长期原则置信度高、中、低。待确认信息不能进入长期原则。
阶段关注状态当前区只展示"当前有效"和"待复核"；已过期、已证伪进入更新记录。
风险等级高：影响客户信任/续约/预算/交付/投诉；中：影响效率或方案质量；低：需要观察。
PM 行动清单固定 5 个当前槽位：必须立刻处理、本周重点推进、下次沟通前准备、持续观察、暂缓但保留机会。
Source 归档保存完整原文，主文档只引用必要摘要和来源，不保存完整聊天或会议全文。

8. 验收标准

  1. PM 能在 Web 端上传一段会议记录并生成结构化品牌知识。
  2. 系统能保存完整原始材料，并能追溯每条关键结论来源。
  3. 新人能通过品牌详情页快速理解品牌当前状态。
  4. AI 能自动生成长期原则、阶段关注、商机风险、PM Top 5 行动和待确认问题。
  5. 无法唯一识别品牌时，不自动入库，必须人工确认。
  6. 长期原则必须包含证据等级和置信度。
  7. 阶段关注必须包含适用时间 / 场景和复核点 / 失效条件。
  8. PM 行动清单始终只有 5 个当前行动槽位。
  9. Markdown 导出文件结构符合：品牌名/品牌名.md 与 品牌名/sources/YYYY-MM-DD_HHmm_来源类型.md。

必须提供

还需要开发前确认

  • 部署环境：本地、内网服务器还是云服务。

  • LLM 服务商、模型名、API Key 管理方式。
  • 是否需要接入真实登录，还是先用团队内测账号。
  • Markdown 导出目录放在服务器、本地文件系统还是对象存储。
  • 第一批试点品牌和 3-5 份真实会议/聊天/复盘材料。
  • 谁负责 AI 自动入库后的抽审。
