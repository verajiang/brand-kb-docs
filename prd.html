MVP Product Requirement Document

品牌服务知识库 MVP 第一版 PRD

把散落在会议、聊天、复盘和 Brief 中的品牌服务信息，转化为可信、可追溯、可持续更新的品牌知识库，让新人和协作方快速理解一个品牌项目。

完整 Web App Postgres 主存储 Markdown 双写导出 AI 自动入库 + 人工抽审

1. 产品定义

一句话定义

品牌服务知识库是一个面向品牌服务团队的项目上下文中枢，帮助每个经手品牌的人快速知道项目背景、当前状态、关键风险、长期原则和下一步行动。

核心闭环

Web 端上传/粘贴沟通记录 → 保存原始材料 → AI 解析结构化品牌知识 → 自动入库，人可抽审 → 生成新人速览看板与 Markdown 归档。

2. MVP 范围

第一版必须包含

  • 品牌项目档案：基础信息、业务阶段、核心目标、主要问题、合作机会。
  • 上游资料输入：粘贴文本、上传文本类文件、选择来源类型、保存完整原始材料。
  • AI 结构化解析：识别品牌、材料类型、长期原则、阶段关注、商机风险、PM Top 5、待确认问题。
  • 自动入库 + 人工抽审：唯一识别品牌时自动入库，无法识别时进入人工确认。
  • 新人速览看板：展示品牌总览、当前重点、原则、风险、行动、问题与更新记录。
  • Markdown 双写导出：数据库为主，同时导出主文档和 source 原文归档。

第一版暂不包含

  • 后台监听微信、飞书、钉钉。
  • 自动读取企业 IM。
  • 完整 OCR 和图片/视频/直播间画面视觉理解。
  • 完整 RBAC 权限体系。
  • 多品牌经营管理驾驶舱。
  • 自动向客户发送消息或替 PM 做业务决策。

3. 用户与场景

PM / 品牌服务负责人

上传沟通记录、更新知识、查看 Top 5 行动、判断风险和商机。

新接手同学

快速了解品牌背景、长期禁忌、当前重点、关键联系人和历史决策。

执行协同方

查看与内容、媒介、投放、直播、数据相关的偏好、禁忌和行动。

管理者

查看品牌服务是否有沉淀，判断当前风险是否被识别和跟进。

一级页面目标关键内容

5. 核心流程

1
Web 端上传 / 粘贴会议、聊天、复盘或 Brief。
2
系统保存完整 source 原始材料，记录来源类型、材料时间、上传人。
3
AI 判断材料类型并提取结构化品牌服务内容。
4
输出长期原则、阶段关注、商机风险、PM Top 5 行动和待确认问题。
5
若能唯一识别品牌则自动入库；否则进入人工确认。
6
品牌看板读取最新数据，并同步生成 Markdown 主文档与 source 归档。

6. 页面原型说明

品牌列表页

包含搜索、新建品牌、上传资料和品牌卡片。品牌卡片展示行业、业务阶段、更新时间、高风险、待确认、行动数和状态。

上传资料页

包含目标品牌、来源类型、材料时间、原始文本、文件上传、自动入库开关和解析结果。

品牌详情页

包含 8 个 Tab，首屏优先展示新人速览：核心目标、主要问题、关键数字、重要行动和高风险。

待确认 / 抽审页

处理品牌缺失、多品牌、低置信度、AI 自动入库抽审，支持确认、修改、撤回。待确认问题需要展示"为什么要确认、问谁、怎么问、确认后写到哪里"。

7. 数据规则

类型规则
证据等级品牌明示、品牌行为、项目结果、服务方观察、待确认。
长期原则置信度高、中、低。待确认信息不能进入长期原则。
阶段关注状态当前区只展示"当前有效"和"待复核"；已过期、已证伪进入更新记录。
风险等级高：影响客户信任/续约/预算/交付/投诉；中：影响效率或方案质量；低：需要观察。
PM 行动清单固定 5 个当前槽位：必须立刻处理、本周重点推进、下次沟通前准备、持续观察、暂缓但保留机会。
行动状态更新当前状态为未开始、进行中、等待外部。PM 可手动更新；新 source 入库时 AI 可建议更新。已完成、已取消或被更高优事项替换的行动从当前 Top 5 移出，并写入更新记录。
待确认问题处理状态为待提问、已提问待回复、已确认、已取消。当前区展示待提问和已提问待回复；已确认后转入对应知识区，已取消后进入更新记录。
标为已提问待回复点击后打开"记录提问动作"表单，填写实际询问对象、提问渠道、提问时间、预计复核时间和实际发出去的问题。保存后状态变为已提问待回复，但不写入知识库结论。
确认并写入知识库点击后打开"填写回复并写入知识库"表单。用户在这里填写对方回复/已确认结论；系统根据问题类型和回复内容自动判断写入位置，并生成结构化摘要。PM 只确认系统建议，必要时走高级修改。保存后系统将摘要写入联系人、阶段关注、长期原则、风险或 PM 行动清单，并关闭该问题。
写入位置判断默认由系统判断，不要求 PM 手选。联系人类问题写入关键联系人；阶段/时间/当前目标类问题写入阶段关注；数据缺口/口径/无法匹配类问题写入风险；完成/等待/推进类回复更新 PM 行动；长期偏好/禁忌/判断标准类回复写入长期原则。
Source 归档保存完整原文，主文档只引用必要摘要和来源，不保存完整聊天或会议全文。

8. 待确认问题示例

待确认问题为什么需要确认问谁建议问法确认后处理
参会角色的真实姓名、所属方和决策关系是什么？ 当前只有说话人编号，影响联系人维护和决策链判断。 会议组织者 / PM 这次会议中的说话人1-4分别是谁？哪些属于品牌方，谁能拍板需求优先级？ 写入关键联系人；补全所属方、影响力、负责事项和当前状态。
618 每日监控的固定交付格式和反馈渠道是什么？ 影响初版看板结构、每日执行节奏和交付预期。 业务需求方 618 每日监控希望几点、通过什么形式反馈？核心必须包含哪些字段？ 写入阶段关注；同步更新 PM 行动清单的产出物和状态。
短视频消耗数据能否通过千川 ID 与罗盘数据匹配？ 决定短视频看板是否能完整评估挂车视频投放效率。 技术 / 数据 千川短视频 ID 与罗盘数据能否稳定匹配？不能时有哪些替代口径？ 可匹配则写入看板方案；不可匹配则写入重点风险。
单品监控看板的目标值由谁输入，粒度到什么级别？ 决定总览诊断勾 / 叉逻辑能否落地。 业务方 目标值是业务人工输入还是运营计划导入？粒度到品类、SPU 还是直播间？ 写入长期判断标准或阶段关注；补充数据字段需求。
下半年直播间销售目标预计何时、由谁输出？ 影响下半年品类、人群和执行动作拆解启动时间。 业务策略方 6 月第一周下半年销售目标由谁确认？会按直播间、品类还是单品拆分？ 拿到目标后更新 PM 行动；延期则保持等待外部并设置复核点。

待确认问题的两个按钮交互

标为已提问待回复

用于记录 PM 已经把问题问出去了，但还没拿到答案。用户需要填写实际询问对象、提问渠道、提问时间、预计复核时间和实际发出去的问题。这个动作只更新问题状态，不产生知识库结论。

确认并写入知识库

用于拿到回复后沉淀结论。回复内容在该按钮打开的表单里填写，包括对方回复/已确认结论、证据等级、确认来源和确认时间。写入位置由系统根据问题类型和回复内容自动判断，PM 只确认建议。保存后问题关闭，结论进入对应知识区。

9. 核心模块示例

关键联系人

示例：说话人2｜品牌方｜强影响人｜负责数据可用性、指标定义、618 监控和下半年规划｜来源：待确认问题回复。

阶段关注

示例：618 每日监控最高优先级｜适用 618 大促期间｜推荐先交付可用初版并建立每日反馈模板｜状态：当前有效。

商机与风险

商机示例：短视频监控看板开发。风险示例：多数据源口径不一致、短视频挂车消耗数据不完整。

更新记录 / Source 追溯

示例：2026-05-21｜待确认问题回复｜新增说话人2确认为品牌方业务负责人｜关闭参会角色确认问题。

10. 验收标准

  1. PM 能在 Web 端上传一段会议记录并生成结构化品牌知识。
  2. 系统能保存完整原始材料，并能追溯每条关键结论来源。
  3. 新人能通过品牌详情页快速理解品牌当前状态。
  4. AI 能自动生成长期原则、阶段关注、商机风险、PM Top 5 行动和待确认问题。
  5. 无法唯一识别品牌时，不自动入库，必须人工确认。
  6. 长期原则必须包含证据等级和置信度。
  7. 阶段关注必须包含适用时间 / 场景和复核点 / 失效条件。
  8. PM 行动清单始终只有 5 个当前行动槽位。
  9. Markdown 导出文件结构符合：品牌名/品牌名.md 与 品牌名/sources/YYYY-MM-DD_HHmm_来源类型.md。
